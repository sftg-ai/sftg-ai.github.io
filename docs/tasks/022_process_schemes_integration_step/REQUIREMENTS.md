# REQUIREMENTS: Внедрение шага «Модуль интеграции» в блок-схемы сценариев

## 1. Бизнес-контекст и проблема
В карточках каталога сценариев автоматизации (`#cases` в `RealCases.jsx`) блок-схема процесса состояла из 3 шагов:
`Вход` ➔ `ИИ-агент` ➔ `Итог`.

Это создавало ощущение, что ИИ-агент напрямую модифицирует базу данных, учетную систему или CRM.
В корпоративном секторе (B2B, промышленность, торговля в Беларуси) для директоров и ИТ-служб критически важно разделение зон ответственности:
- ИИ-агент занимается интеллектуальной обработкой (распознавание, классификация, подготовка параметров);
- **Модуль интеграции** — надежная программа в закрытом контуре заказчика (сервер или защищенное облако), которая исполняет детерминированный код, валидирует данные и совершает транзакции в Битрикс24, 1С и базах компании;
- Учетная система получает гарантированно проверенный результат.

## 2. Бизнес-требования
1. Ввести 4-й этап в схему процесса с плашкой **«Модуль интеграции»**.
2. Общая структура цепочки:
   - **Вход** (канал или источник данных: чат, фото, скан, отклик)
   - **ИИ-агент** (интеллектуальное действие: анализ, сборка, расчет)
   - **Модуль интеграции** (детерминированное исполнение: валидация, запрос остатков, запись в 1С/Битрикс24)
   - **Итог** (готовый результат: заказ, проводка, наряд, сводка)
3. Сохранить гибкость: если у сценария задано поле `flow.integration`, рендерится 4-шаговая цепочка, если нет — плавно работает 3-шаговая.
4. Строгий корпоративный стиль без кричащих цветов: плашка «Модуль интеграции» выполняется в аккуратном сдержанном стиле (светлый фон, четкий шрифт, без радужных градиентов).
5. Язык строго без птичьего жаргона и без процентов (`%`), Битрикс24 всегда на первом месте.

## 3. Критерии приемки
- Во всех применимых сценариях каталога отображаются 4 четких шага процесса.
- В дизайне соблюдена сетка 4px и отступы, карточки остаются сбалансированными по высоте.
- Сборка `npm run build` проходит с кодом 0.
